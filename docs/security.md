# Bosta Integration Security

## Scope

Phase 1 stores and protects company-specific Bosta Dashboard configuration. It
does not log in to the Dashboard, create browser sessions, scrape orders, or
synchronize any Odoo business documents.

## Encryption

Dashboard passwords are encrypted with `cryptography.fernet.Fernet`, which
provides authenticated encryption. The encryption key is read only from the
server environment variable:

`BOSTA_DASHBOARD_ENCRYPTION_KEY`

The key must:

- be a valid Fernet key;
- be supplied consistently to every Odoo worker;
- be backed up using the organization's secret-management process;
- never be stored in PostgreSQL or Odoo system parameters; and
- never be committed to Git, `.env` files, logs, screenshots, or support dumps.

A key can be generated administratively with the Fernet key-generation API. Do
not paste the generated value into documentation or source control.

Changing or losing the key makes previously encrypted Dashboard passwords
undecryptable. Key rotation therefore requires a controlled re-encryption plan;
Phase 1 does not implement automatic rotation.

## Password lifecycle

- The `dashboard_password_input` field is non-stored and masked in the form.
- A non-empty input is encrypted before the model record is written.
- Blank input leaves the existing encrypted value unchanged.
- The saved encrypted value never appears in list, form, or search views.
- Clearing the password requires the manager-only **Clear Saved Password**
  action, which also disables the integration and updates the audit fields.
- The password, encryption key, and encrypted token are never included in
  errors or logs generated by this module.

## Access control

- **Bosta Integration Manager:** full CRUD access to configuration records for
  allowed companies.
- **Bosta Integration User:** no access to configuration records or credentials.
- The Manager group implies the User group.
- No users are assigned to either group automatically.

The record rule uses the active allowed-company list (`company_ids`), not only
the current company. This permits an authorized multi-company manager to access
all selected allowed companies while preventing access to other companies.

## Deployment checklist

1. Install the maintained `cryptography` package in the Odoo Python environment.
2. Set one valid `BOSTA_DASHBOARD_ENCRYPTION_KEY` for all Odoo workers.
3. Restart Odoo after changing the environment.
4. Assign the Bosta Integration Manager group only to authorized administrators.
5. Verify company assignments and allowed-company context.
6. Never commit credentials, cookies, browser profiles, or session-state files.
